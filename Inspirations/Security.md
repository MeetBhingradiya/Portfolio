# Security Framework

## Client & Server Communication Security on DevTools
- Server Data is Securely Verified with Signature before Accepting any Response from Server

## 🚀 Deployment Protection & DDoS Mitigation

- 🌐 **Cloudflare Protection**: Active until domain expiration (1 year). If expired, fallback to **Vercel's Protection**.
- 🔒 **Trace API**: Specially designed so only browsers can access the APIs.
- 🛡️ **reCAPTCHA**: Implemented for login and registration security.
- 🧩 **Advanced Extension Interference Detection**: Prevents React hydration issues caused by browser extensions.

---

## 🔑 Administration Access Control

- 🏰 **Admin Panel Access**: Restricted exclusively to passkeys.
- 🔏 **Passkey Setup Requirements**:
  - Must be set with **Admin Secret Key + TOTP** (Authenticator key stored securely in the database).
  - 📌 An **undisclosed secret page** is used for authentication setup (not exposed in the repository).
  - ⚙️ Requires `AdminPasskeySetup = true` in the database for activation.
  - ✅ Once a passkey is set, `AdminPasskeySetup` automatically resets to `false`.
- ⏳ **Session Management**:
  - ⏰ **7-day session timeout** if inactive; resets with continuous usage.
  - 🛡️ **Single Admin Account** with real-time activity logging (IP, location, browser, device, etc.).

```ts
{
    // ? Collection : State
    "id": "#Startup",  // Only accessible via `.env` for privacy
    "AdminPasskeySetup": false
}
```

## 🔐 User Accounts Security (Session, Authentication & Verification)

- 🔑 **Credential Encryption**:
  - 🔒 Login credentials are **encrypted using a public key** before transmission.
  - 🔓 The server **only receives encrypted data** and decrypts it using an **active private key**.
  - 🔁 Active private keys are randomly generated by admins, ensuring secure data transfers.

```ts
// ? Collection: RSAKeys
{
    "isActive": true,
    "privateKey": "ActivePrivateKey",
    "publicKey": "ActivePublicKey",
    "generatedAt": "2025-xx-01T00:00:00.000Z", // Auto-generated on request
    "expiresAt": "2025-xx-01T23:59:59.999Z", // Auto-generated on request
    "permissions": [
        "localStorage", // 🗄️ Used in LocalStorage encryption
        "cookies", // 🍪 Used in Cookie session encryption
        "login", // 🔑 Used in Login encryption
        "register", // 📝 Used in Registration encryption
        "payment", // 💳 Used in Payment encryption
        "otp" // 📲 Used in OTP encryption
    ]
}
```

- 🔄 **User Sessions**:
  - Follow the same encryption security measures as **admin sessions**.
  - 🔑 **LocalStorage & Cookies** use **separate encrypted keys**.
  - 🚨 Even if **both encryption keys are stolen**, access is restricted unless:
    - 📡 **User-Agent & Platform Data** (Device Name, Trace Token Signature) match.
    - ❌ If mismatched, **session access is blocked**, and the session is immediately revoked.

---

## 💳 Payment Security

- ❌ **No Card Data Stored**: Payments are processed entirely via **Razorpay**.
- 🔏 **RSA Digital Signatures**: Used to secure Razorpay webhooks.

---

## 🖥️ Client-Side Browser Protection

- 🛑 **Developer Tools Restrictions**:
  - ⛔ `F12` & `Ctrl + Shift + I` **are disabled** to prevent unauthorized access.
  - 🚫 **Right-click** functionality is **disabled**.
  - 🔍 **Debugger Trap** & **Console Warnings** alert users attempting to inspect the page.
  - 🔄 Even if **F12 is opened before loading the site**, additional **security traps** are implemented.

---

## Signup & Verification Security
- 📧 **Email Verification**:
  - 📥 **Email Verification Link** is sent to the user's email.
  - 📝 **Verification Code** is required to complete the registration process.
  - 📅 **Verification Link Expiry**: 24 hours. if account not verifyed within 24 hours account will be discarded 


## 📜 Summary

This security framework ensures robust **deployment protection, account security, encryption standards, and client-side access restrictions**. Any future security updates should be documented and reviewed periodically to maintain high standards of protection.
